# 🧩 예산

- Programmers ID: 12982
- Official link: https://school.programmers.co.kr/learn/courses/30/lessons/12982
- Level: 1
- Stage: Level 1 Core 25
- Prerequisites: 리스트, `sorted()`, 누적합, 조건문
- Core concepts: 작은 비용부터 선택, 그리디 입문

## 🎯 이 문제에서 배우는 것

최대한 많은 대상을 고르려면 어떤 순서로 선택해야 하는지 이유를 설명합니다.

## 🔎 문제 핵심

리스트 `d`에는 각 부서가 요청한 금액이 있습니다. `budget` 안에서 지원할 수 있는 부서 수의 최댓값을 돌려줍니다. 선택한 부서에는 요청한 금액 전부를 지원해야 합니다.

## 💭 먼저 생각해 보기

요청 금액이 `[6, 2, 4]`이고 예산이 6이라면, 6을 먼저 고르는 경우와 작은 금액부터 고르는 경우를 비교해 보세요.

## 🧪 예제 이해하기

6을 먼저 지원하면 부서 한 곳만 지원합니다. 2와 4를 지원하면 같은 예산으로 두 곳을 지원합니다. 따라서 결과는 2입니다.

## 🛠️ 풀이 1. 이해하기 쉬운 방법

### 💡 아이디어

작은 요청부터 정렬한 뒤 예산 안에 들어오는 동안 선택합니다. 같은 수의 부서를 고른다면 작은 금액들로 고른 쪽의 합계가 가장 작습니다. 비싼 요청을 더 싼 요청으로 바꾸어도 부서 수는 같고 비용은 늘지 않기 때문입니다.

### 🐍 Python 코드

```python
def solution(d, budget):
    requests = sorted(d)
    spent = 0
    supported = 0
    for amount in requests:
        if spent + amount > budget:
            break
        spent += amount
        supported += 1
    return supported
```

### 📖 코드 해설

`break`는 현재 반복문을 끝냅니다. `return`과 달리 함수 전체를 바로 끝내지는 않습니다. 정렬되어 있으므로 현재 금액을 감당할 수 없다면 뒤의 금액도 감당할 수 없습니다. 지금까지 작은 금액부터 부서를 골랐습니다. 여기서 한 곳을 더 고르는 가장 싼 방법조차 예산을 넘었으므로 현재 부서 수에서 멈춰도 됩니다. 이런 식으로 매 단계에서 유리한 선택을 하는 방법을 그리디라고 합니다. 다른 문제에서도 통하려면 선택이 옳은 이유를 따로 확인해야 합니다.

### ⏱️ 시간 복잡도

부서 수를 `n`이라 하면 정렬에 최악 `O(n log n)`, 한 번 순회하는 데 `O(n)`이 듭니다. 전체는 `O(n log n)`이며 한 부서라면 일정한 작업으로 끝납니다.

### 💾 공간 복잡도

`sorted(d)`는 길이 `n`인 새 리스트를 만들고 정렬 중에도 임시 공간을 씁니다. 반환값을 포함한 추가 공간은 `O(n)`입니다. 입력 `d`는 바꾸지 않습니다.

## ⚠️ 실수하기 쉬운 점

- 예산과 합계가 같으면 지원할 수 있습니다. `>=`가 아니라 `>`일 때 멈춥니다.
- 부서에 요청 금액의 일부만 지원해서 한 곳으로 세면 안 됩니다.
- 정렬하지 않은 상태에서 예산을 넘는다고 멈추면 뒤쪽의 더 싼 요청을 놓칠 수 있습니다.
